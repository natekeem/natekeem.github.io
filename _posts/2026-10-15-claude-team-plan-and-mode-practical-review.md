## "또 복붙해야 해?" 매일 아침 반복되던 컨텍스트 피로

AI를 활용해 블로그 시스템을 구축하고 40편이 넘는 영문 글과 기술 문서를 작성·검수하다 보면, 개발자로서 가장 먼저 맞닥뜨리는 병목은 '프롬프트의 질'이 아니라 **'컨텍스트 주입의 피로도'**였습니다.

새 대화 세션을 열 때마다 우리가 정한 프로젝트 규칙을 다시 설명해야 했습니다.
- "우리는 북미 40대 단독주택 소유자를 타깃으로 해."
- "이 저장소는 Astro 기반이고, Tailwind를 써."
- "가짜 체험담(I tested) 쓰지 말고, 안전 규정(UL, CPSC)을 인용해."

ChatGPT Plus나 Claude Pro를 쓸 때도 나름대로 메모장에 시스템 프롬프트를 저장해두고 매번 복사해서 붙여넣었지만, 파일이 10개가 넘어가고 코드베이스가 커지자 대화창 하나를 띄우기 위해 준비해야 하는 시간만 5~10분이 걸렸습니다. 그러다 실수가 나오면 AI는 금세 기존 코드 컨벤션을 잊어버리고 엉뚱한 라이브러리를 임포트하곤 했습니다.

이 컨텍스트 지옥에서 벗어나고자 앤트로픽(Anthropic)이 출시한 **Claude Projects**와 **Claude Team 플랜(월 $30/인, 최소 5인 결제)**을 직접 결제해 프로덕션 파이프라인에 태워봤습니다. 

과연 월 150달러(약 20만 원)라는 최소 비용을 지불할 가치가 있었을까요? 한 달간 3개 블로그와 배포 인프라를 굴리며 체감한 솔직한 장단점을 가감 없이 공유합니다.

---

## 1. Projects 기능의 핵심: 200k 토큰 '영구 메모리'의 위력

Claude의 **Projects(프로젝트)** 기능은 단순한 폴더 정리가 아닙니다. 핵심은 **"특정 목적을 가진 작업 공간에 최대 200,000 토큰(책 한 권 분량)의 지식 베이스(Project Knowledge)를 상시 고정해두는 것"**입니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│                   CLAUDE PROJECTS 아키텍처 다이어그램                  │
├────────────────────────────────────────────────────────────────────────┤
│ [ Project: The Smart Suburbanite ]                                     │
│   ├── Project Knowledge (영구 고정 문서 200k 토큰)                    │
│   │   ├── style_guide.md (Warm Utility Editorial 톤)                  │
│   │   ├── safety_standards.md (UL 325, NEC 전기 규범 요약)             │
│   │   └── guideTaxonomy.ts (실제 사이트 카테고리/슬러그 코드)          │
│   ├── Custom Instructions (Mode 설정)                                  │
│   │   └── "엔지니어링 팩트와 수치 위주로 서술하고 접속사 남발 금지"   │
│   └── Shared Chats (팀원 간 컨텍스트가 유지된 대화 스레드)             │
└────────────────────────────────────────────────────────────────────────┘
```

### 실제로 무엇이 달라졌는가?
1. **코드와 정책의 상시 동기화**:
   - `sites.json`, `guideTaxonomy.ts`, 그리고 작성 가이드라인 마크다운을 프로젝트 지식(Knowledge)에 한 번 업로드해두면, 새 채팅창을 열자마자 "차고 문 오프너 글을 기획해줘" 한마디만 던져도 알아서 기존 카테고리(`comfort-convenience`)의 슬러그 규칙과 배선 주의사항을 숙지한 상태로 답변을 시작합니다.
2. **환각(Hallucination)의 급격한 감소**:
   - 일반 챗봇은 모르는 내용이 나오면 그럴듯한 거짓말을 지어내지만, 프로젝트 지식에 공식 표준(UL 규정, API 사양서)을 넣어두면 "업로드된 문서에 따르면..."이라며 근거를 바탕으로 대답하기 시작합니다.

## 2. 모드(Mode)와 커스텀 인스트럭션의 실전 분리

Claude Projects 안에서는 **'Set Project Instructions'**를 통해 해당 프로젝트 전체에 적용될 행동 양식을 강제할 수 있습니다. 저는 이를 일종의 **'역할별 가상 모드(Mode)'**로 쪼개어 활용했습니다.

* **모드 A. [Fact-Check Auditor 모드]**:
  - 인스트럭션: *"너는 까다로운 테크 저널 팩트체커다. 제출된 초안에서 출처가 불분명한 수치, 제조사 마케팅 문구, 검증되지 않은 안전 보장 표현을 모조리 찾아내 지적하라."*
* **모드 B. [Front-End Refactoring 모드]**:
  - 인스트럭션: *"너는 Astro와 TailwindCSS 시니어 개발자다. 컴포넌트 분리, 빌드 타임 정적 라우팅 최적화, 불필요한 번들 사이즈 감소 관점에서만 코드를 리뷰하라."*

대화마다 시스템 프롬프트를 길게 적을 필요 없이, 프로젝트 자체를 **'에디토리얼 검수용 프로젝트'**와 **'Astro 프론트엔드용 프로젝트'**로 물리적으로 분리해두니 모드 전환이 1초 만에 이루어졌습니다.

## 3. Artifacts(아티팩트): 대화창과 분리된 인터랙티브 작업대

Claude 3.5 Sonnet과 함께 도입된 **Artifacts(아티팩트)**는 특히 프론트엔드 코드나 다이어그램을 짤 때 진가를 발휘했습니다.

기존 대화형 AI는 긴 코드를 짜주면 채팅창 스크롤이 수십 킬로미터씩 밀려서 이전 대화를 찾기 힘들었습니다. 하지만 Artifacts는 화면 우측에 독립된 코드 에디터 겸 프리뷰 창을 띄워줍니다.

- **React 컴포넌트 실시간 렌더링**: 테마에 들어갈 버튼이나 비교 카드를 만들면 우측에서 바로 클릭해보고 디자인을 검증할 수 있습니다.
- **버전 관리(Version History)**: "여기 폰트 크기 좀 줄여줘", "반응형 그리드로 바꿔줘"라고 요청하면 아티팩트 상단에 v1, v2, v3 슬라이더가 생겨 이전 코드로 즉시 롤백할 수 있습니다.

## 4. 냉정한 현실: 1인 개발자에게 Team 플랜이 안겨준 통증

장점만 보면 환상적이지만, 실제로 결제 버튼을 누르고 한 달을 굴려본 뒤 마주한 현실적인 장벽들도 분명했습니다.

### ① 5인 최소 결제 조건 (월 $150의 고정비)
가장 큰 장벽입니다. 1인 개발자나 2인 소규모 사이드 프로젝트 팀이라도 Claude Team 플랜을 쓰려면 **무조건 5개 시트(Seat)를 결제해야 합니다.**
- 연간 결제 시: $25 × 5 = **월 $125 (약 17만 원)**
- 월간 결제 시: $30 × 5 = **월 $150 (약 20만 원)**

혼자 쓰는데 나머지 4개 계정의 비용을 고스란히 허공에 날려야 한다는 점은 1인 부트스트래퍼에게 결코 가벼운 금액이 아닙니다.

### ② 생각보다 빨리 닫히는 사용량 한도 (Usage Limit)
Team 플랜은 Pro 플랜에 비해 사용량이 대폭 늘어난다고 안내되어 있지만, 200k 토큰짜리 대형 프로젝트에서 긴 코드베이스를 여러 번 주고받다 보면 **2~3시간 만에 "사용량 한도에 도달했습니다" 메시지를 마주하게 됩니다.**
결국 급한 불을 끄기 위해 로컬에서 Anthropic API를 직접 호출하거나 다른 LLM을 보조로 써야 하는 상황이 생깁니다.

## 5. 결론: 누가 Team 플랜을 결제해야 할까?

한 달간의 실전 테스트 끝에 내린 제 기준은 명확합니다.

| 상황 및 환경 | 추천 플랜 | 현실적인 판단 이유 |
| :--- | :--- | :--- |
| **순수 1인 개발자 / 개인 블로거** | **Claude Pro ($20/월)** | Pro 플랜에서도 개인용 Projects 기능이 지원됩니다. 굳이 5개 시트($150)를 결제할 이유가 없습니다. |
| **3인 이상 실제 개발/콘텐츠 팀** | **Claude Team ($30/인)** | 프로젝트 지식(Knowledge), 시스템 프롬프트(Mode), 대화 히스토리를 팀원 간에 클릭 한 번으로 공유할 수 있어 온보딩 비용이 제로가 됩니다. |
| **대규모 자동화 파이프라인 구축** | **Anthropic API + 로컬 CLI** | 웹 UI 한계와 시트당 고정비에 얽매이지 않고, 토큰 사용량만큼만 지불하는 API 방식이 경제적입니다. |

### 나태킴의 한 줄 커밋 코멘트
> *"Projects의 컨텍스트 고정은 혁명이었지만, 1인 개발자라면 Pro 플랜의 개인 Projects만으로도 90%의 효용을 뽑아낼 수 있다. 도구의 이름값보다 내 워크플로우의 크기를 먼저 측정하자."*
